# THREADROOM / 07 — ระบบเชื่อม Google Sheets

หน้าเว็บใช้ GitHub Pages ผู้สั่งยืนยันอีเมลด้วย OTP และแอดมินเข้าด้วยรหัส 6 หลัก ตรวจสิทธิ์ที่เซิร์ฟเวอร์ มีการยืนยันเสื้อสองแบบ แก้ไข/ล้างตัวเลือก บันทึกประวัติ และคิวอีเมลแจ้งเมื่อแอดมินแก้รายการ

## สถานะตอนนี้

โค้ดเป็นโหมดใช้งานจริงแล้ว ไม่มีฐานข้อมูลคำสั่งซื้อใน localStorage หากยังไม่ใส่ URL ของ Apps Script หน้าเว็บจะแสดงว่ารอเชื่อมต่อ และไม่รับคำสั่งซื้อหรือยอมให้เข้าระบบแอดมินจากการตรวจรหัสในเบราว์เซอร์

ยังต้องติดตั้งและ Deploy Apps Script ในบัญชีเจ้าของก่อน ระบบจึงจะบันทึกข้อมูลจริงได้ การทดสอบอัตโนมัติใช้ Google Services จำลอง ไม่ใช่หลักฐานว่าส่งอีเมลจริงหรือ Deploy Google สำเร็จแล้ว

## ติดตั้งครั้งแรก

1. เปิด [ชีตฐานข้อมูล](https://docs.google.com/spreadsheets/d/1S4waTYrvCnnWEjIgObwnwoGG_ynNyAGIEEanP25L_lY/edit) → ส่วนขยาย → Apps Script
2. คัดลอก [Code.gs](apps-script/Code.gs) ลงไฟล์ Code.gs ใน Project Settings เปิดการแสดงไฟล์ manifest แล้ววาง [appsscript.json](apps-script/appsscript.json) ด้วย ตรวจเมนู Services ว่ามี Google Sheets API v4 หากใช้ Google Cloud project ที่ตั้งเองต้องเปิด API นี้ใน project ด้วย
3. เลือกฟังก์ชัน **setup** แล้ว Run และอนุญาตสิทธิ์ Google รหัสเริ่มต้นได้เตรียมเป็น hash ในชีตส่วนตัวแล้ว setup จะย้ายไปเก็บใน Script Properties และล้างข้อมูลสำหรับติดตั้งออกจากชีตโดยอัตโนมัติ
4. เลือก Deploy → New deployment → Web app ใช้ Execute as: **Me** และ Who has access: **Anyone** แล้ว Deploy บัญชีองค์กรบางแห่งต้องได้รับอนุญาตจากผู้ดูแลโดเมน
5. คัดลอก URL ที่ลงท้าย **/exec** ส่งให้ผู้พัฒนาตั้งค่า หรือใส่ในช่อง apiUrl ของ [dist/config.js](dist/config.js) แล้ว commit ไป main
6. เปิดหน้าเว็บ เข้าทางแอดมินด้วยรหัสที่กำหนด ตรวจแบบและไซซ์ แล้วเปิดรับจากหน้าตั้งค่าระบบ

ผู้ติดตั้งต้องเป็นเจ้าของชีตหรือมีสิทธิ์แก้ไข และต้องเป็นผู้อนุญาตสิทธิ์ Google ด้วยตัวเอง URL /exec เป็นที่อยู่บริการ ไม่ใช่รหัสแอดมิน

หากทำสำเนาชีตหลังจากติดตั้งไปแล้ว และไม่มีข้อมูลตั้งต้น ให้ตั้ง **ADMIN_PIN** เป็นรหัส 6 หลักใน Script Properties ก่อนรัน setup รหัสจะถูกแปลงเป็น hash และลบค่าอ่านได้ออก ห้ามใส่รหัสจริงในไฟล์บน GitHub หรือ config.js

## การทำงาน

- แต่ละคนต้องเลือกครบทั้ง 2 แบบ ยืนยันแยกตัวได้ สถานะครบเซ็ตเมื่อยืนยันทั้งสองแบบ
- เลือกทรงตรง/ทรงเว้าได้ทุกคน หุ่นชาย/หญิงไม่กำหนดสิทธิ์การสั่ง
- เปลี่ยนไซซ์/ทรงได้จนปิดระบบ เซิร์ฟเวอร์ตรวจเวลาปิดและ revision เพื่อป้องกันการเขียนทับรายการเก่า
- แอดมินแก้หรือล้างตัวเลือกบางแบบ/ทั้งสองแบบได้ ต้องระบุเหตุผล ระบบเก็บก่อน/หลังและผู้แก้ไว้ใน AuditLog
- คำสั่งซื้อ ประวัติ คิวอีเมล และรหัสกันคำขอซ้ำ บันทึกด้วย Sheets batchUpdate เดียว
- เมื่อแอดมินแก้ ระบบเข้าคิว Outbox และ trigger ส่งอีเมลทุก 5 นาที มีสถานะ pending/sent/failed และลองใหม่สูงสุด 3 ครั้ง
- ผู้สั่งใช้ OTP อีเมล 8 หลัก อายุ 10 นาที กรอกได้ 5 ครั้ง session ผู้สั่งมีอายุ 12 ชั่วโมง
- แอดมินใช้รหัส 6 หลัก session มีอายุ 2 ชั่วโมง กรอกผิด 5 ครั้งจะพักการเข้าสู่ระบบ 15 นาที อีเมลของผู้สั่งไม่ให้สิทธิ์แอดมินโดยอัตโนมัติ
- การส่งอีเมลขึ้นอยู่กับโควตาของบัญชี Google ตรวจคิวได้ใน Outbox หากแก้ต้นเหตุแล้ว รัน retryFailedEmails() เพื่อเข้าคิว failed ใหม่

## ตารางข้อมูล

Orders, AuditLog, Users, Settings, AuthCodes, Sessions, Outbox และ Requests เก็บไว้ในชีตส่วนตัว ห้ามเปิดแชร์ข้อมูลหรือ publish-to-web ให้ผู้สั่งอ่านชีตโดยตรง ผู้สั่งเข้าถึงเฉพาะรายการตนเองผ่าน API

Settings มีข้อมูลตั้งต้นสำหรับการติดตั้งในแถวซ่อน setup จะล้างค่านี้เมื่อเก็บใน Script Properties สำเร็จ การอ่าน bootstrap ของเว็บส่งออกเฉพาะสถานะเปิด/ปิด เวลา และสถานะการเชื่อมต่อ ไม่ส่ง hash หรือ secret

## ใส่เสื้อและไซซ์จากผู้ผลิต

แบบโปโลกรมท่าและเสื้อยืดครีมในเวอร์ชันนี้เป็นตัวอย่าง ต้องแทนด้วยแบบจริงของรุ่นก่อนเปิดรับ เปลี่ยนรายละเอียดใน PRODUCTS และ measurements() ที่ dist/domain.mjs ใส่ภาพหน้า/หลังใน dist/assets/ แล้วตั้ง artwork ใน config.js ใช้ path แบบ relative

ถ้ารายชื่อไซซ์เปลี่ยน ให้ปรับทั้ง SIZES ใน domain.mjs และ ALLOWED_SIZES ใน Code.gs หากทั้งสองแบบเป็นแพตเทิร์นอื่น ต้องปรับ mesh ใน mannequin.mjs ให้ตรงด้วย เมื่อยืนยันตารางจริงแล้วจึงตั้ง Settings/sizesConfirmed เป็น true

หุ่น 3 มิติเป็นภาพประมาณการ ไม่มีการจำลองการทิ้งตัว/ความยืดของผ้า หรือข้อมูลสแกนตัวบุคคล การเปลี่ยนไซซ์ปรับ mesh จริง แต่ควรวัดเสื้อมาตรฐานจากผู้ผลิตก่อนสั่ง

## ตรวจระบบก่อนเปิดรับ

ใช้ Node.js 22 ขึ้นไป ไม่ต้องติดตั้ง package เพิ่ม

```bash
node --test tests/*.test.mjs
```

มีการทดสอบกติกา ขอบเขตสิทธิ์ผู้สั่ง/แอดมิน รหัส PIN การพักเมื่อกรอกรหัสผิด การเก็บ session การปิดรับ revision การล้างประวัติ การบันทึกแบบ atomic และการไม่แสดงผลสำเร็จเมื่อยังไม่เชื่อมต่อ

หลัง Deploy ต้องทดสอบกับบัญชีอีเมลที่คุณควบคุมอีกครั้ง: รับ OTP → ยืนยัน 1 แบบ → ยืนยันอีกแบบ → แอดมินเปลี่ยน/ล้าง → ตรวจ AuditLog/Outbox → ตรวจอีเมล → ปิดรับและลองแก้อีกครั้ง
